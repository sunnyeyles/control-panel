# packages/user-storage

Guidance moved out of the root `CLAUDE.md` so it loads only when working in this package.

**`@workspace/user-storage` hides the AWS SDK behind one module.** `s3-user-object-store.ts` is the only file _in that package_ that imports `@aws-sdk/client-s3`, and `apps/dashboard/lib/storage.ts` is the only file outside it — it constructs an `S3Client` in order to attach Vercel's OIDC credential provider, and passes it in through the store's `client?: S3Client` option. That option exists for exactly this. **Do not add a `credentials` option to the package**; its own comment explains why ("Note what is _not_ here: any way to pass credentials"), and a package that accepts a credential is a package someone eventually hard-codes a key into. Everything else depends on the `UserObjectStore` interface — or, better, on the narrow `BriefStore` / `ResumeStore` / `CoverLetterStore` / `TailoredResumeStore` facades over it, which know their kind's key shape and file types so a call site cannot get them wrong.

**`CoverLetterStore` and `TailoredResumeStore` are two facades over one core.** Both are **Posting Documents** — see `CONTEXT.md` — so `posting-document-store.ts` holds the key shape, the metadata round trip and all five operations, and each facade supplies its kind, the metadata key its instant lands under, and the name it calls that instant. **Add a third kind by adding a facade, never by widening the core with a flag.** Two things must not be "tidied": the instant keys stay `drafted-at` and `generated-at` (both are stamped on objects that already exist, and there is no copy-onto-itself to rename them with), and `CoverLetterProvenance` stays without `sourceDocument`, because omitting the field is what makes a letter's lack of one a decision rather than an unset option. Call `createS3UserObjectStore()` only at a composition root: same `createX()` factory rule as the agents, and for the same reason — constructing one reads configuration, so a module-level instance would move that failure to import time.

Four things about that package are load-bearing and easy to undo by accident:

- **Object keys are `{environment}/{userId}/{kind}/…tail.{ext}`, and `userId` sits above `kind` deliberately** — erasing a user is then one prefix, not one per kind. The segment validation in `keys.ts` is the ownership boundary, not a tidiness rule: an unvalidated `userId` of `../someone-else` addresses another user's prefix.
- **Retention is driven by an object _tag_, not a key prefix.** S3 lifecycle filters take no wildcards, so with `userId` in the middle there is no prefix meaning "every user's briefs". Every object is tagged `kind=<kind>` at write time and the Terraform lifecycle rules filter on that — which is why the IAM policies must grant `s3:PutObjectTagging`, and why a kind added to `kinds.ts` without a matching `object_kinds` entry in Terraform silently gets no retention at all.
- **Content types are derived from the extension, never accepted from the caller,** against a per-kind allowlist in `kinds.ts`. A caller-supplied media type would let a `.pdf` be stored as `text/html`. Uploaded kinds are also stored `Content-Disposition: attachment`.
- **Object metadata is HTTP headers, so every value from outside goes through `metadata.ts`.** A newline in a value is header injection and a non-ASCII character is silently mangled. `toMetadataValue` strips a value to printable ASCII; `toMetadataRecord` does a whole provenance record and drops what leaves nothing behind. An uploaded filename (`resume-store.ts`) and a **Posting Document**'s provenance — the Run, the title, the company, the URL, and the name of the Document a tailored resume was rewritten from (`posting-document-store.ts`) — are all model- or user-supplied text and all use it. Do not write a fresh regex at a new call site — that is exactly how the filename rule came to be the only one.

**`resume-store.ts`'s metadata is written and never read back.** A Document's filename and its Document Type are columns on `documents` in Postgres; `original-filename` and `document-type` are still stamped on the object so that the bucket stays self-describing, and nothing in the application consults them. That is why `StoredResume` has no `documentType` field, and why `NewResume.documentType` is a plain `string` — **do not add a `DocumentType` union or an allowlist to this package.** The valid set is `DOCUMENT_TYPES` in `@workspace/db` plus a CHECK on the column, and this package must not depend on `@workspace/db` to learn it. The stripping above is the reason the filename moved: a header value cannot carry an em dash, and `text` can.
